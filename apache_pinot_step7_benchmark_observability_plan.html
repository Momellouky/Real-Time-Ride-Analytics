Step 7 Implementation Plan

Benchmarking & Observability for the event-driven Apache Pinot ride analytics lab. This step adds runtime performance metrics directly to the v2 dashboard so load, latency, ingestion freshness, CPU, and memory can be observed while increasing event throughput.

Scope: Step 7 onlyFastAPI + VueLocal machine metricsPinot query latencyIngestion lag50–1000 events/sec tests

1. Goal

Extend the v2 demo so the dashboard shows not only business analytics, but also how the system behaves under increasing load. The purpose is to observe when higher Kafka ingestion throughput begins to affect Pinot query latency, ingestion freshness, CPU usage, or memory usage.

Success condition: while the generator is running, the dashboard should continuously show actual EPS, Pinot query latency, Pinot ingestion lag, total ingested events, CPU usage, and RAM usage.

4. Add system metrics dependency

Add:

psutil

Example service:

import psutil


def get_system_metrics() -> dict:
    memory = psutil.virtual_memory()

    return {
        "cpu_percent": psutil.cpu_percent(interval=None),
        "memory_percent": memory.percent,
        "memory_used_gb": round(memory.used / (1024 ** 3), 2),
        "memory_total_gb": round(memory.total / (1024 ** 3), 2),
    }

5. Measure Pinot query latency

Measure latency around every Pinot query in the shared Pinot client so all dashboard queries contribute to the same benchmark data.

from collections import deque
from time import perf_counter


class PinotMetrics:
    def __init__(self, max_samples: int = 500):
        self.latencies_ms = deque(maxlen=max_samples)

    def record_latency(self, latency_ms: float) -> None:
        self.latencies_ms.append(latency_ms)

Wrap query execution:

async def query(self, sql: str, **kwargs):
    started = perf_counter()

    try:
        return await self._execute_query(sql, **kwargs)
    finally:
        latency_ms = (perf_counter() - started) * 1000
        self._metrics.record_latency(latency_ms)
Keep a bounded rolling window, for example the latest 500 Pinot queries, so memory usage does not grow forever.

6. Calculate avg, p95, and p99

def percentile(values: list[float], percentile_value: float) -> float:
    if not values:
        return 0.0

    values = sorted(values)
    index = int(round((percentile_value / 100.0) * (len(values) - 1)))
    return values[index]


def latency_summary(samples) -> dict:
    values = list(samples)

    if not values:
        return {"avg_ms": 0.0, "p95_ms": 0.0, "p99_ms": 0.0, "sample_count": 0}

    return {
        "avg_ms": round(sum(values) / len(values), 2),
        "p95_ms": round(percentile(values, 95), 2),
        "p99_ms": round(percentile(values, 99), 2),
        "sample_count": len(values),
    }

7. Calculate Pinot ingestion lag

Ingestion lag is the difference between current time and the newest event visible in Pinot for the active simulation.

Pinot query

SELECT MAX(event_timestamp) AS latest_event_timestamp
FROM operations
WHERE simulation_id = 'SIMULATION_ID'

FastAPI calculation

from time import time


def calculate_ingestion_lag_ms(latest_event_timestamp: int | None) -> float:
    if latest_event_timestamp is None:
        return 0.0

    now_ms = int(time() * 1000)
    return max(0.0, now_ms - latest_event_timestamp)
This is application-visible freshness, not raw Kafka consumer-group lag. For this lab it answers the practical question: “How old is the newest event I can query from Pinot?”

SELECT COUNT(*) AS total_ingested_events

10. Backend endpoint hot code

@router.get("/api/v2/benchmark/metrics")
async def get_benchmark_metrics(request: Request):
    generator = request.app.state.generator
    pinot = request.app.state.pinot

    simulation_id = generator.simulation_id
    generator_stats = generator.get_stats()
    system_stats = get_system_metrics()

    if not simulation_id:
        return {
            "simulation_id": None,
            "generator": generator_stats,
            "pinot": {
                "total_ingested_events": 0,
                "events_not_yet_visible": 0,
                "ingestion_lag_ms": 0,
                "query_latency": pinot.metrics.latency_summary(),
            },
            "system": system_stats,
        }

    count_rows, latest_rows = await asyncio.gather(
        pinot.query(TOTAL_INGESTED_SQL.format(simulation_id=simulation_id)),
        pinot.query(LATEST_EVENT_SQL.format(simulation_id=simulation_id)),
    )

    ingested = count_rows[0]["total_ingested_events"]
    latest_ts = latest_rows[0]["latest_event_timestamp"]

    return {
        "simulation_id": simulation_id,
        "generator": generator_stats,
        "pinot": {
            "total_ingested_events": ingested,
            "events_not_yet_visible": max(0, generator_stats["generated_events"] - ingested),
            "ingestion_lag_ms": calculate_ingestion_lag_ms(latest_ts),
            "query_latency": pinot.metrics.latency_summary(),
        },
        "system": system_stats,
    }

12. Frontend polling model

const MAX_POINTS = 300;

async function refreshBenchmark() {
  const metrics = await getBenchmarkMetrics();

  history.value.push({
    timestamp: Date.now(),
    actualEps: metrics.generator.actual_events_per_second,
    avgLatency: metrics.pinot.query_latency.avg_ms,
    p95Latency: metrics.pinot.query_latency.p95_ms,
    p99Latency: metrics.pinot.query_latency.p99_ms,
    ingestionLag: metrics.pinot.ingestion_lag_ms,
    cpu: metrics.system.cpu_percent,
    memory: metrics.system.memory_percent,
  });

  if (history.value.length > MAX_POINTS) {
    history.value.shift();
  }
}
Keeping benchmark chart history in the browser is enough for this step. There is no need to persist observability metrics into Pinot yet.

14. Controlled benchmark procedure

  2. Record average/p95/p99 latency, ingestion lag, CPU, and RAM.
  3. Repeat at 100 events/sec.
  4. Repeat at 250 events/sec.
  5. Repeat at 500 events/sec.
  6. Try 1000 events/sec only if memory and ingestion lag remain healthy.

15. How to interpret the results

  • Actual EPS below target: generator or Kafka producer may be the bottleneck.
  • Generated events rise but Pinot count lags: ingestion is not keeping up.
  • Ingestion lag grows continuously: sustained load exceeds current ingestion capacity.
  • p95/p99 rises while avg stays low: tail-latency degradation is starting.
  • RAM approaches machine limit: stop increasing load before swapping distorts the benchmark.
  • CPU near saturation: observe whether query latency or ingestion freshness degrades at the same time.

16. Tests

  • Latency samples never exceed the rolling-window size.
  • Empty latency window returns zeros.
  • p95/p99 calculations return valid values.
  • Ingestion lag never becomes negative.
  • Benchmark endpoint works when no simulation is active.
  • Benchmark endpoint reports current simulation only.
  • Generated minus ingested count is never negative.
  • Frontend benchmark history remains bounded.
  • Dashboard continues updating if one benchmark request temporarily fails.
